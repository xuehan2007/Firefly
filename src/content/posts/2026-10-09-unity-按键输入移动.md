# unity 按键输入移动


---


旧版输入系统（Input Manager）给了两类读法，回答的是两种不同的问题：
写法	回答的问题	典型用途

Input.GetKey(KeyCode.W)	这一帧键按着吗（按住期间一直为真）	持续按住往前走

Input.GetKeyDown(KeyCode.Space)	这一帧刚按下吗（只有按下的那一帧为真）	跳跃、开火这类一次性动作

Input.GetAxis("Horizontal")	这根轴的值是多少（静止 0，左/右 −1 到 +1，带平滑过渡）	平滑的移动输入

    GetKey 问的是「键」：参数是具体的键，键盘上每个键都能问。
    GetAxis 问的是「轴」：参数是轴的名字，左右两组键先被 Input Manager 折算成一个 −1 到 +1 的数。

轴名从哪来：菜单 Edit > Project Settings > Input Manager，里面有 Axes 列表。工程默认配好了 Horizontal（左右）、Vertical（前后）、Jump（空格），对照如下：


| 键盘按键 | 轴名（Axes） | 读到的值 |
| --- | --- | --- |
| ← → | Horizontal | 左 −1、右 +1、松开 0 |
| ↓ ↑ | Vertical | 后 −1、前 +1、松开 0 |
| 空格 | Jump | 按住 1、松开 0 |


轴名必须和配置逐字一致：代码写 "Horizontal"，配置里也得叫 Horizontal，多一个字母少一个字母都读不到。
## 简单按键移动脚本


```c#
using UnityEngine;

public class InputDemo : MonoBehaviour          // 挂在对象上的脚本
{
    public float moveSpeed = 5f;               // 每秒移动 5 格；想慢一半就改成 5 / 2

    void Update()                              // 每帧问一次输入的地方
    {
        // 第 1 段 · 读：拿到这一帧的方向值
        float h = Input.GetAxis("Horizontal"); // 左右：−1 ~ +1
        float v = Input.GetAxis("Vertical");   // 前后：−1 ~ +1

        // 第 2 段 · 判：空格刚按下的那一帧才进来一次
        if (Input.GetKeyDown(KeyCode.Space))
        {
            Debug.Log("跳跃！");               // 先用日志确认输入真的进来了
        }

        // 第 3 段 · 动：把方向值变成位置变化
        // 新位置 = 旧位置 + 方向 × 每秒速度 × 本帧间隔秒数
        transform.position = transform.position
            + new Vector3(h, 0f, v) * moveSpeed * Time.deltaTime;
    }
}
```
## 添加刚体(rigidbody)后的移动脚本
### 基本框架

```c#
using UnityEngine;

public class RigidbodyMove : MonoBehaviour
{
    private Rigidbody rb;

    void Start()
    {
        rb = GetComponent<Rigidbody>();
    }

    void FixedUpdate()  // 物理用 FixedUpdate，不是 Update
    {
        // 移动逻辑写这里
    }
}
```
为什么用 FixedUpdate？
物理系统按固定时间步跑（默认 0.02 秒），FixedUpdate 和它同步，不会因为帧率波动导致抖动。

## 四种实现方法
### 方法1: MovePosition（推荐，精准移动）

```c#
using UnityEngine;

public class MoveExample : MonoBehaviour
{
    public float speed = 5f;      // 移动速度
    private Rigidbody rb;

    void Start()
    {
        rb = GetComponent<Rigidbody>();
    }

    void FixedUpdate()
    {
        // 读键盘输入（左右、前后）
        float h = Input.GetAxis("Horizontal");  // A/D 或 ←/→
        float v = Input.GetAxis("Vertical");    // W/S 或 ↑/↓

        // 算出这一帧要移动多远
        Vector3 move = new Vector3(h, 0f, v) * speed * Time.fixedDeltaTime;

        // 移动到 当前位置 + 位移
        rb.MovePosition(rb.position + move);
    }
}
//rb.position 是刚体的位置（和 transform.position 差不多，但物理上更准）

//Time.fixedDeltaTime 是固定时间步，不是 Time.deltaTime

//MovePosition 参数是目标位置，不是位移量，所以要 当前位置 + 位移
```
### 方法2：MoveRotation（旋转）
让刚体平滑旋转到指定角度。

```c#
void FixedUpdate()
{
    // 每秒转 90 度
    Quaternion deltaRot = Quaternion.Euler(0f, 90f * Time.fixedDeltaTime, 0f);

    // 在现有旋转基础上叠加
    rb.MoveRotation(rb.rotation * deltaRot);
}
//Quaternion.Euler(x, y, z)：把欧拉角转成四元数

rb.rotation * deltaRot：在现有旋转上叠加这次旋转

如果写成 deltaRot * rb.rotation，是绕世界轴转，效果不同
**适合**
需要精确控制旋转角度的场景。
```
### 方式 3：velocity 直接设速度（最常用）
直接给刚体一个速度，物理引擎自己处理后续运动。

```c#
public float speed = 5f;
private Rigidbody rb;

void Start()
{
    rb = GetComponent<Rigidbody>();
}

void FixedUpdate()
{
    float h = Input.GetAxis("Horizontal");
    float v = Input.GetAxis("Vertical");

    // 设水平速度，保留 Y 轴速度（这样重力还能让它下落）
    Vector3 newVelocity = new Vector3(h * speed, rb.velocity.y, v * speed);
    rb.velocity = newVelocity;
}
```
### 方法 4：AddForce（受力移动）
给物体施加力，让它自己加速运动，最有“物理感”。
```c#
public float force = 10f;
private Rigidbody rb;

void Start()
{
    rb = GetComponent<Rigidbody>();
}

void FixedUpdate()
{
    float h = Input.GetAxis("Horizontal");
    float v = Input.GetAxis("Vertical");

    Vector3 direction = new Vector3(h, 0f, v);
    rb.AddForce(direction * force);
}
```

四种 ForceMode

| 模式 | 特点 | 适合 |
| --- | --- | --- |
| Force | 受质量影响，持续推 | 真实物理 |
| Acceleration | 不受质量影响，持续推 | 统一加速 |
| Impulse | 受质量影响，瞬间冲量 | 跳跃、爆炸 |
| VelocityChange | 不受质量影响，瞬间 | 跳跃 |


### 方式 5：角速度旋转（自转最简单）

```c#
void Start()
{
    rb = GetComponent<Rigidbody>();
    // 每秒转 90 度 = 90 * Mathf.Deg2Rad 弧度/秒
    rb.angularVelocity = new Vector3(0f, 90f * Mathf.Deg2Rad, 0f);
}
```
单位是弧度/秒，所以要乘 Mathf.Deg2Rad

想停下就设 rb.angularVelocity = Vector3.zero

想加速用 rb.AddTorque(...)
**适合**
悬浮道具、旋转平台、金币。

## 刚体重要设置
四种碰撞检测的区别：
离散的（Discrete）：

原理：默认设置。Unity 每一帧算一次碰撞。如果球在 A 帧在桌子左边，B 帧在桌子右边，它就会无视桌子直接飞过去（也就是常说的“穿模”）。

适用：移动非常慢的物体，或者静态物体。

持续（Continuous）：

原理：开启连续检测。Unity 会在球移动到当前位置的路径上，提前算一次碰撞。但它只对静态物体（比如墙壁、桌子边缘）有效，不检测其他快速移动的物体。

适用：主角、玩家控制的物体。

连续动态（Continuous Dynamic）：

原理：最强的防穿透模式。它既检测静态墙壁，也检测其他开启了“持续”或“连续动态”的刚体。

适用：你当前的情况——滚得快的小球、子弹、抛射物。虽然消耗性能稍大，但能极大降低穿模概率。

Continuous Speculative：

原理：比“连续动态”更省性能的算法，通过预测下一帧位置来算碰撞。有时会有点“幽灵碰撞”（还没碰到就弹开），但对玩家操作的物体很友好。

适用：玩家角色或需要大量刚体的游戏。
插值（Interpolate）—— 解决视觉卡顿
物理原理：Unity 的物理引擎在 FixedUpdate（默认 0.02 秒一次）里计算位置，而画面渲染在 Update（帧率不固定）里执行。两者的频率不一致。

通用作用：让物体在画面上的移动变得平滑。如果不开启，快速移动的物体在视觉上会显得“一顿一顿”的（俗称“物理抖动”）。

一般选择：

无 (None)：适用于完全静止的物体，或者对视觉平滑度要求极低的场景。

插值 (Interpolate)：绝大多数情况下的默认推荐。根据上一物理帧和当前物理帧的位置进行平滑过渡，手感最扎实。

外推 (Extrapolate)：根据上一帧的位置和速度，预测下一帧的位置。画面最丝滑，但在发生碰撞时可能会出现瞬间的“穿模再弹开”的视觉假象。

2. 约束（Constraints）—— 控制物体的自由度
物理原理：现实世界物体有 6 个自由度（3 个位置轴 X/Y/Z，3 个旋转轴 X/Y/Z）。约束就是用来锁死其中的某些轴。

通用作用：防止物体在物理模拟下产生不期望的位移或翻转。

一般选择：

冻结位置 (Freeze Position)：常用于 2D 游戏或 2.5D 游戏（比如只允许在 XY 平面移动，就冻结 Z 轴）。或者防止角色跳跃时因为微小碰撞而偏离轨道。

冻结旋转 (Freeze Rotation)：最常用的约束。比如一个第一人称角色的胶囊体，必须冻结所有旋转，否则它走路撞到墙就会摔倒；再比如一个不需要翻倒的箱子，需要冻结 X 和 Z 轴的旋转。

3. 质量与阻力（Mass, Drag, Angular Drag）—— 运动与衰减
质量 (Mass)：决定物体的惯性。

通用作用：质量越大，改变其运动状态（加速或停止）越难，碰撞时给其他物体施加的力也越大（比如卡车撞小汽车）。

一般选择：通常设为 1（标准单位，比如 1kg）。除非有特殊受力需求，否则不用大改。

线性阻力 (Drag / Linear Damping)：模拟空气阻力或地面摩擦对平移的影响。

通用作用：数值越大，物体停止移动得越快。设为 0 时，物体在太空中会永远匀速直线运动。

一般选择：角色控制器通常在 0~1 之间；掉落的物品或自由落体通常为 0；需要快速刹车的载具可能在 2 以上。

角阻力 (Angular Drag)：模拟旋转时的空气阻力。

通用作用：数值越大，物体停止旋转得越快。

一般选择：通常默认 0.05 即可。如果需要物体旋转后迅速停下（比如抽奖转盘），可以调大；如果需要持续旋转，调小或为 0。

4. 物理材质（Physic Material）—— 表面摩擦与弹性
物理原理：这不是刚体本身的属性，而是挂在碰撞体（Collider）上的组件。它决定了两个物体接触时表面的物理特性。

通用作用：精确控制碰撞时的“触感”和反弹力度。Unity 有默认材质，但你想微调手感时必须自己建。

一般选择（核心参数）：

动态摩擦力 (Dynamic Friction)：滑动时的阻力。数值 0 表示像冰面一样滑；数值 1 表示非常涩，推不动。

静态摩擦力 (Static Friction)：从静止到开始移动的阻力。

弹性 (Bounciness)：碰撞时的反弹程度。0 表示完全不反弹（如泥巴），1 表示完全弹性碰撞（如理想弹力球）。

摩擦合并 (Friction Combine) / 弹性合并 (Bounce Combine)：决定两个物体碰撞时，以谁的参数为准（平均、最小、最大、相乘）。通常默认 平均 (Average) 即可。

### 物理材质
🛠️ 第一步：创建物理材质
在 Unity 左下角的 项目窗口 (Project) 空白处，右键点击。

选择 创建 (Create) -> 物理材质 (Physic Material)。（注意：Unity 6 及新版中可能直接叫 Physics Material）。

给它起个有意义的改名，比如 IceMaterial（冰面）或 BouncyMaterial（弹力）。

🛠️ 第二步：配置核心参数
选中刚创建的物理材质，在右侧 Inspector 面板中，你会看到以下核心参数：

动态摩擦力 (Dynamic Friction)：物体正在滑动时的阻力。

范围 0~1。设为 0 就像在冰面上滑行，几乎无阻力；设为 1 就像在粗糙的水泥地上，滑不远。

静态摩擦力 (Static Friction)：物体从静止到开始滑动所需的阻力。

范围 0~1。通常比动态摩擦力略大一些，这样物体在斜坡上才能保持静止。

弹性 (Bounciness)：碰撞时的反弹程度。

范围 0~1。0 代表完全不反弹（如泥巴），1 代表完全弹性碰撞（如完美的弹力球）。

摩擦力合并 (Friction Combine) / 弹性合并 (Bounce Combine)：

当你把两个物理材质不同的物体碰在一起时（比如冰面撞到水泥地），听谁的？默认是 平均 (Average)。

如果想让更滑的一方决定接触结果，可以改成 最小 (Minimum)。

🛠️ 第三步：挂载到碰撞体上（最重要的一步）
物理材质不能拖给刚体，必须拖给碰撞体 (Collider)。

在层级窗口，选中你想要改变物理属性的物体。

在右侧 Inspector 里，找到它的碰撞体组件（比如 Box Collider、Sphere Collider、Capsule Collider 或 Mesh Collider）。

找到碰撞体组件里的 材质 (Material) 槽位。

把刚才创建好的物理材质，从项目窗口拖到这个槽位里。

💡 第四步：常见的组合与应用场景
做冰面关卡：创建一个 IceMaterial，动态摩擦力 = 0，静态摩擦力 = 0。把它拖给冰面地面的 Collider。这样任何物体在上面都会不受控制地滑行。

做弹跳机关：创建一个 BouncePadMaterial，弹性 = 1，摩擦力 = 0.5。把它拖给弹簧床的 Collider。角色掉上去会被弹飞。

做角色（防止卡墙）：给角色的碰撞体挂一个摩擦力 = 0 的材质。因为很多 3D 游戏角色是靠代码控制移动的，如果角色身上有摩擦力，贴着墙壁走时会被墙壁“粘住”或减速。

默认状态：如果你没给物体挂物理材质，Unity 会自动使用内置的默认材质（摩擦力约 0.6，弹性 0）。

⚠️ 常见避坑与冷知识：
材质合并的优先级：两个物体相撞，如果一个是默认材质（摩擦0.6），另一个是冰材质（摩擦0），按照默认的 平均 规则，摩擦系数就是 (0.6+0)/2 = 0.3，就不是绝对滑了。所以做冰面时，通常要把地面的物理材质的 摩擦力合并 改为 最小 (Minimum)，这样只要有一方是0，最终摩擦就是0。

2D 游戏的物理材质：如果你在做 2D 游戏，物理材质叫 Physics Material 2D，参数略有不同（只有摩擦力和弹性），创建方式是在项目窗口右键 -> Create -> 2D -> Physics Material 2D。

性能消耗极低：物理材质只是一个数据配置，对性能几乎没有影响，可以放心在每个物体上使用不同的材质来调整手感。

总结一句话：建个材质 -> 调摩擦力和弹性 -> 拖给物体的 Collider。 你只需要记住，它是挂在 Collider 上的，而不是 Rigidbody 上就行！
