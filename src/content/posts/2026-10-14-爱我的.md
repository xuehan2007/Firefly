# Animator 组件

Controller：指向 Animator Controller 资源，也就是状态机所在的地方。

Apply Root Motion：是否让动画带动物体自身位移。像素风 2.5D 项目里角色位移由脚本控制，通常关掉，否则角色会被动画的根位移推着乱跑。

Culling Mode（剔除模式）：物体不在画面/不在视野内时是否继续播动画。

 
Unity 的主循环（PlayerLoop）把一帧切成若干阶段，彼此有固定先后:
   FixedUpdate：按固定步长执行，物理与带 Rigidbody 的脚本落在这一段，一帧里可能跑零次到多次。
   Update：所有 MonoBehaviour 的 Update 在这里依次执行。

   PreLateUpdate：这一段的 DirectorUpdate 子阶段里，Animator 采样参数、推进状态机、求值动画曲线，并把姿态结果写进 Transform。

   PostLateUpdate：LateUpdate 在这里执行，之后渲染提交。

于是得到一帧内的顺序：Update 里下命令 → Animator 在 PreLateUpdate 里结算 → LateUpdate 里能看到结算结果。

由此可以推出两条容易踩坑的结论：

 在 Update 里调用 SetTrigger 或 SetBool，只是把值写进 Animator 的参数表；动画的真正切换要等到这一帧的 DirectorUpdate 阶段才发生。

   同一帧的 Update 里，SetTrigger 之后立刻读 GetCurrentAnimatorStateInfo，拿到的还是上一帧结算出的状态。想在本帧读到新状态，得把读取放到 LateUpdate，或者等下一帧。


```c#
// 一帧里的先后（阶段名按 PlayerLoop 的实际命名）
// Update():                     读输入 → SetBool / SetTrigger
// PreLateUpdate.DirectorUpdate: 采样参数 → 推进状态机 → 求值曲线 → 写 Transform
// PostLateUpdate.LateUpdate:    动画已结算，此时读状态信息才是本帧结果

private Animator animator;

void Update()
{
    if (Input.GetKeyDown(KeyCode.J))
    {
        animator.SetTrigger("Attack");

        // 同一帧立刻读：拿到的是上一帧结束时的结算结果
        AnimatorStateInfo info = animator.GetCurrentAnimatorStateInfo(0);
        Debug.Log(info.shortNameHash);
    }
}

void LateUpdate()
{
    // 放到这里读，才是这一帧的结算结果
    AnimatorStateInfo info = animator.GetCurrentAnimatorStateInfo(0);
}
```
**也就是说Update 只负责‘下达指令’，而真正的动画结算发生在 PreLateUpdate 阶段。**
## Animator 的 Update Mode（更新模式）详解
在 Unity 的 Animator 组件面板中，有一个关键的设置叫 Update Mode，它决定了动画在 PlayerLoop 中的具体执行时机。它有且仅有以下三个选项：

1. Normal（默认模式）
👉 执行时机：Update 之后，LateUpdate 之前（即我们之前讲的 PreLateUpdate.DirectorUpdate 阶段）。

适用场景：绝大多数常规游戏逻辑。

底层逻辑：在 Update 里写完 SetTrigger 等参数后，Animator 会在 PreLateUpdate 阶段统一结算。这样能保证 LateUpdate 里读取到的是最新状态，也能保证 LateUpdate 里的骨骼修正逻辑不会覆盖动画结果。

2. Animate Physics（物理同步模式）
👉 执行时机：FixedUpdate 之后（与物理系统步调一致）。

适用场景：需要与 Rigidbody（刚体）精确交互的动画。例如：角色踩在移动的平台上、布娃娃系统（Ragdoll）、机械臂抓取物理物体。

底层逻辑：此时动画不会每渲染帧更新，而是跟着物理步长走。如果你的项目使用此模式，那么写参数和读状态的代码可能就需要配合 FixedUpdate 或 OnAnimatorMove 来写。

3. Unscaled Time（不受时间缩放影响模式）
👉 执行时机：Update 之后（与 Normal 相同），但忽略 Time.timeScale。

适用场景：UI 动画、游戏暂停菜单里的角色动画、或者独立于游戏时间流逝的加载动画。

底层逻辑：当游戏 Time.timeScale = 0（暂停）时，Normal 模式的动画会冻结，但 Unscaled Time 模式下的动画会继续播放。

# 状态机（State Machine）里只有两样零件，看懂这两个词，状态机就看懂了：

   状态 State：一个方块，里面放着当前正在播的那段 AnimationClip。「Idle（站立）」「Run（奔跑）」「Attack（攻击）」各是一个状态。

   过渡 Transition：一条箭头，意思是「满足条件后，从这个状态换到那个状态」。箭头是单向的，从 A 指向 B 只代表 A 能去 B；想来回切就要画两条。
