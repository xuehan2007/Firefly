# unity物体穿过触发和碰撞


---



| 模式 | Is Trigger | 接触时发生什么 | 用于 |
| --- | --- | --- | --- |
| 实心模式 | 不勾选 | 互相挡住，物理引擎算出推开与弹开 | 地面、墙壁、角色身体 |

## FixedUpdate 与物理步

脚本里最常见的两个函数，Update 与 FixedUpdate，区别在于调用时机：

    Update 每画面帧调用一次，帧率是多少就调多少次，快慢随机器。
    FixedUpdate 按固定时间间隔调用，每次间隔相同，与画面帧率无关。

物理引擎的推算就发生在每次 FixedUpdate 之后：引擎每走一个固定步长，算一遍速度与位置。把与物理有关的代码放进 Update，会出现两种毛病——画面帧率与物理步长对不上，物理表现抖动；同一段逻辑在快机器与慢机器上执行次数不同，结果不一致。

分工由此明确：读键盘输入、界面逻辑写在 Update；改刚体速度、给刚体施加力，写在 FixedUpdate。
## 简单碰撞和触发脚本

```c#
using UnityEngine;

public class Coin : MonoBehaviour
{
    // 触发器回调：别的碰撞体进入本触发区域时，Unity 自动调用
    private void OnTriggerEnter(Collider other)
    {
        Debug.Log("捡到了：" + other.gameObject.name);
    }

    // 实心碰撞回调：两个实心碰撞体刚接触时，Unity 自动调用
    private void OnCollisionEnter(Collision collision)
    {
        Debug.Log("撞到了：" + collision.gameObject.name);
    }
}
```
## 注意事项
### 一、 重力（Gravity）：不只是全局下落
全局重力与局部重力

全局重力：在 Edit -> Project Settings -> Physics 里，默认是 (0, -9.81, 0)。这模拟了地球重力。

局部重力：刚体（Rigidbody）上有个 使用重力 (Use Gravity) 开关。如果你做的是太空游戏、无人机、或者悬浮物体，必须取消勾选。如果取消勾选，物体就不会自动下坠。

自定义重力（特殊需求）

如果游戏需要“倒转重力”或“行星引力”，不要去改全局重力，而是关掉刚体的 Use Gravity，然后在 FixedUpdate 里用 rb.AddForce() 手动施加一个向下的力。

重力手感微调

很多动作游戏（尤其是平台跳跃类）发现 9.81 太飘了，手感不好。通常会去 Project Settings -> Physics 把重力 Y 轴改为 -20 到 -30，让角色下落更“干脆”。

对应的，如果你的项目里有两个不同大小的世界（比如正常世界和微缩世界），不要随便改全局重力，而是给微缩世界的物体挂一个施加额外重力的脚本。

### 二、 碰撞（Collision）：性能与准确性的博弈
图层碰撞矩阵（Layer Collision Matrix）—— 最重要的性能优化

在哪里：Project Settings -> Physics -> Layer Collision Matrix。

作用：默认情况下，所有图层互相碰撞。如果你有 100 个子弹和 100 个敌人，系统会计算一万次碰撞检测，游戏瞬间卡死。

通用做法：分层。比如把玩家设成 Player 层，环境设成 Environment 层，子弹设成 Bullet 层。在矩阵里取消勾选 Bullet 和 Bullet 的碰撞（子弹不碰子弹），能省下巨量性能。

碰撞体形状（Collider Shape）—— 性能第二杀手

基础几何体（Box、Sphere、Capsule）：性能开销极小，是首选。

网格碰撞体（Mesh Collider）：开销巨大，尽量只在静态物体（如地形、场景建筑）上使用。

凸包（Convex）：如果你必须给一个复杂形状的物体加 Mesh Collider，一定要勾选 Convex（凸包）。但凸包不能用在有凹陷的物体上。

复合碰撞体（Compound Colliders）：如果一个物体形状复杂（比如一把枪），不要用 Mesh Collider。在它的子物体上挂几个 Box Collider 拼凑起来，父物体挂一个 Rigidbody。性能和精度兼得。

触发器（Trigger）与碰撞（Collision）

物理碰撞：双方必须有 Collider，其中一方有 Rigidbody，且没有勾选 Is Trigger。会触发 OnCollisionEnter，会产生物理反弹。

触发检测：双方必须有 Collider，其中一方有 Rigidbody，且其中一方勾选了 Is Trigger。会触发 OnTriggerEnter，不会产生物理反弹，会直接穿过去（用于拾取道具、到达区域、伤害判定）。

碰撞检测模式（Collision Detection）

慢速物体选 离散的 (Discrete)。

快速移动物体（子弹、赛车、掉落的石头）必须选 连续动态 (Continuous Dynamic)。如果不选，它们会直接穿透薄墙（这叫“隧穿效应”）。

物理材质（Physic Material）的合并规则

当冰面（摩擦力 0）撞上粗糙地面（摩擦力 1），最终摩擦力是多少？默认是 平均 (Average)，即 0.5。

如果你想让冰面绝对滑，去把地面的材质的 摩擦力合并 (Friction Combine) 改为 最小 (Minimum)。

### 三、 必须避开的代码与执行坑（极其重要）
物理操作必须在 FixedUpdate 里

所有 Rigidbody.AddForce、rb.velocity 赋值、rb.MovePosition 等，必须放在 FixedUpdate 里，不能放在 Update 里。否则物理效果会随帧率变化而飘忽不定。

绝对不要直接修改 transform.position

如果你在 Update 里用 transform.position = ... 移动一个带刚体的物体，相当于是在物理系统计算完之后，强行瞬移了它。这会破坏物理引擎的连续性，导致穿模、碰撞丢失、抖动。

正确做法：用 rb.MovePosition()（平滑移动），或者 rb.velocity（物理速度），或者干脆把 isKinematic 设为 true（让物理系统不干预，完全代码控制）。

运动学刚体（Is Kinematic）

勾选 Is Kinematic 后，刚体不再受重力、碰撞力、推力影响。它只能被你用代码移动（比如 transform.Translate 或 rb.MovePosition）。

用途：移动平台、被玩家控制但物理不互动的角色。注意：Kinematic 刚体可以推开普通刚体，但普通刚体推不动它。

刚体睡眠（Sleeping）

物理引擎很聪明，物体静止一段时间后会自动进入“睡眠”以节省性能。

如果你用代码瞬间移动了一个正在睡觉的物体，它可能“醒不过来”，导致没碰撞。这时候需要调用 rb.WakeUp()。

### 四、 常见问题快速排查表

四、 常见问题快速排查表

**物体一直往下掉，穿过了地板	**
1. 地板没加 Collider；2. 物体移动太快，没开 连续动态；3. 物体和地板的 Layer 在碰撞矩阵里被取消了勾选。

**物体碰到东西没反应，直接穿过去**	
1. 碰撞双方的 Layer 被屏蔽；2. 其中一方勾选了 Is Trigger。

**刚体移动时画面抖动	**
1. 没开启 插值 (Interpolate)；2. 代码写在了 Update 里；3. 相机跟随逻辑不对（比如应该放在 LateUpdate）。

**物体会莫名其妙飞出去（弹飞）**
1. 穿模后物理引擎强行推出，产生了巨大弹力；2. 物理材质弹性过大；3. 碰撞体尺寸和模型严重不符。

**斜坡上物体慢慢往下滑	**
物理材质的 静态摩擦力 (Static Friction) 太小，调大即可。
总结一句话：
三维物理的核心就是“管好图层（分层少算）、用对碰撞体（少用Mesh）、代码放对地方（FixedUpdate）、移动用对方法（别乱改transform）”。把这四件事做好，90% 的物理 bug 都会绕着你走。
